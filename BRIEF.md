## Треки (один на команду, менять нельзя)
### A — Приколы (Pranks)
Интерактивный «слой» поверх существующих экранов. **Не должен блокировать** основной сценарий.
- Плюс: контент грузится с CDN → меняется без релиза
- Пример: тряхнул телефон → анимация, но путь в платежи не блокируется
- Нельзя: перекрывать экраны платежей/переводов/реквизитов/лимитов; блокировать ввод дольше эффекта; тормозить запуск
- Референс: Blackbox (управление сенсорами устройства)

### B — Игры (Games)
HTML5-страница, открывается внутри приложения (WebView). **Нативные игры не принимаются.**
Три приоритетных домена обучения:
- **Финграмотность:** цена vs ценность, копить vs тратить, бюджет, вклад/кредит
- **Soft skills:** эмоции, дружба, разрешение конфликтов, критическое мышление, тайм-менеджмент
- **Безопасность:** мошенничество и социнженерия, подозрительные ссылки, незнакомцы в чатах, давление, «дропы», бытовая безопасность 6–7 лет

Бизнес-требования к игре:
1. Цель обучения одной фразой ("после игры ребёнок умеет/знает/различает…")
2. Механика должна ПРИМЕНЯТЬ знание (иначе это викторина с картинками)
3. Объяснять ошибки, давать повтор, без ругани
4. Сессия 3–5 минут, реиграбельна
5. Наблюдаемое действие = признак, что научился
6. Потеря прогресса не должна фрустрировать; один запуск → финальный результат
7. Звук не автоплей + тумблер

## Технические ограничения
### Без бэкенда
- Можно: новые CMS-ключи для JSON, статические HTTPS-файлы, бандл-ресурсы, localStorage, локальный Bluetooth, существующие возможности приложения без изменения контрактов
- Нельзя: новые эндпоинты/контракты, менять форматы ответов, свой сервер/очереди, матчмейкинг, лидерборды, кросс-юзер пуши, сторонние бэкенды/облака
- Следствие: нет онлайн-мультиплеера; сравнение только с собой/бенчмарком; стейт на устройстве, теряется при переустановке

### Бизнес-ограничения
- Нет лотерей/рулетки/азартных механик (случайная награда — только если ребёнок ничего не тратит и не рискует + дана модель вероятностей)
- Нет авторизации, нет материальных наград, соц.фичи только через Bluetooth
- Нет живых внешних ссылок/QR, нет не-Сбер брендов/конкурентов, нет поп-культурного IP, нет реалистичного оружия
- ФЗ-436, рейтинг 0+/6+

### Игры (Track B) — жёстко
- Только чистые HTML/CSS/JS. **Никаких библиотек/фреймворков/движков** (Phaser, Three.js, Unity WebGL, CSS-фреймворки, шаблонизаторы) — ни с CDN, ни локально
- Сборщики можно, но в выводе — ноль стороннего кода
- Полностью автономно: без внешних API/CDN/шрифтов/аналитики/трекеров/iframe/новых окон
- Относительные пути. WebView без кэша → игра перекачивается каждый запуск
- localStorage и cookies чистятся при каждом открытии/закрытии → каждая сессия с нуля
- Вибрация и шеринг — через канал сообщений, не через browser API

### Канал сообщений (страница → приложение)
`window.postMessage`, 5 типов событий:
- `CLOSE_EVENT`, `FINISH_EVENT`, `COMPLETED_EVENT` (слать один раз; засчитывает прогресс курса), `VIBRATION_EVENT`, `SHARING_EVENT`
- Канал односторонний: нет доступа к данным, авторизации, платежам, файлам

### Бюджеты производительности
- Запуск/главный экран: без замедления
- Анимации: 60 fps
- Ассеты прикола: ≤ 6 МБ
- Полный пакет игры: ≤ 5 МБ
- Первый играбельный экран: ≤ 3 сек на мобильной сети
- Прирост размера приложения: ≤ 3 МБ

## Стек Сбер-приложения (контекст для «реализуемости»)
Две раздельные нативки, без кроссплатформы.
- **Android:** Kotlin 2.2.21, Jetpack Compose, Lottie, Media3/ExoPlayer, WebView, Coil, OpenGL ES. Мин. Android 8. JDK 21.
- **iOS:** Swift 6, SwiftUI+UIKit, Lottie, AVFoundation, WKWebView, Metal. Мин. iOS 15. Xcode 26.5.
- Устройства: только телефоны, русский язык, портрет основной, ширина 360–430pt (~9:19.5).

## Снижают оценку
Основной флоу не завершается, манипуляции, данные/платежи покидают устройство, дарк-паттерны, краш на демо.
Track A: прикол блокирует приложение, блок ввода, одноразовость.
Track B: внешние интеграции, превышение бюджета, сессия >10 мин, не заявлена цель обучения.
